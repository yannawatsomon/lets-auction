# ข้อกำหนด Product Catalog

**สถานะ:** Open (รอยืนยัน) · **ขนาดงาน:** M · **ความเสี่ยงต่อกำหนดส่ง:** ปานกลาง — ต้องใช้ข้อมูลการประมูลและยังมีข้อกำหนดที่ต้องตกลง

## ที่มา

Issue [#38](https://github.com/yannawatsomon/lets-auction/issues/38) ใช้บันทึกข้อตกลงก่อนพัฒนาหน้า Catalog โดยอ้างอิง
[`requirement/product-catalog.md`](../../requirement/product-catalog.md) และข้อกำหนด Highlights กับตัวกรองประเภทประมูลใน
[#63](https://github.com/yannawatsomon/lets-auction/issues/63)

ณ วันที่ 2026-11-11 checkout นี้มีเพียง Rails scaffold และ schema ของแอปยังว่างอยู่ ฟิลด์ auction/lot ใน #28 และการจัดการเวลาประมูลใน #35 ยังเป็นข้อกำหนด ไม่ใช่โค้ดที่พัฒนาแล้วใน checkout นี้ จึงต้องประสานงานก่อนเขียน query

## ข้อกำหนดที่ผู้ใช้ระบุแล้ว

- **ปรับ UI ตามไฟล์อ้างอิงและแสดงเพียงหนึ่งแถว:** ผู้ใช้ส่ง `auction-redesign.html`
  (2026-11-11) ให้ยึดรูปแบบ UI เป็นหลัก หน้าแรกแสดง 3/2/1 ใบต่อสถานะตามจอใหญ่/
  แท็บเล็ต/มือถือ และกด “ดูเพิ่มเติม” เพื่อเปิดรายการสถานะนั้นพร้อมตัวกรองเดิม
  ที่ `/catalog` แทนการขยายหลายแถวบนหน้าแรก การโหลดเพิ่มเติมแบบเดิมยังใช้ในหน้ารายการเต็ม

- **ใช้ Catalog เป็นหน้าแรก:** ผู้ใช้ขอให้แทน homepage เดิมด้วยหน้านี้ (2026-11-11)
  ใช้ฟอร์มค้นหาและล้างตัวกรองที่ `/` ร่วมกับ component เดิม ข้อมูลจำลองยังจำกัดเฉพาะ
  development/test; production แสดงส่วนรายการว่างจนกว่าจะเชื่อมข้อมูลจริง
  **Superseded (2026-11-11):** ผู้ใช้ขอ deploy พร้อมข้อมูลตัวอย่าง จึงอนุญาตให้
  production แสดง Catalog demo แบบอ่านอย่างเดียวตามข้อกำหนดด้านล่าง

### ข้อมูลตัวอย่างบน production (ผู้ใช้ร้องขอ 2026-11-11)

- **แสดงข้อมูล Catalog ตัวอย่างบน Railway:** เปิดเป็นค่าเริ่มต้นชั่วคราว ปิดได้ด้วย
  `CATALOG_DEMO=false` ผ่าน config `catalog_demo_in_production` เพราะผู้ใช้ต้องการ
  ทดลองหน้า Catalog และโหลดเพิ่มเติมด้วยข้อมูลจริงที่มองเห็นได้บนเว็บไซต์
  (ข้อมูลที่แสดงยังเป็นข้อมูลจำลอง ไม่ใช่สินค้าประมูลจริง) ข้อแลกเปลี่ยนคือผู้ชมสาธารณะ
  จะเห็นรายการตัวอย่าง จึงต้องมีแถบแจ้งชัดเจน ไม่เลือกการ seed สินค้าลงฐานข้อมูลจริง
  เพราะเสี่ยงปะปนกับ inventory จริง แหล่งที่มา: คำขอผู้ใช้ “อัพขึ้น railway พร้อมข้อมูลด้วย”
- ขอบเขตเฉพาะการแสดงรายการและตัวกรอง ไม่เปิด mock login, สิทธิ์ admin,
  การเสนอราคา หรือ preview endpoint ใน production เพิ่มเติม
- ใช้ 45 รายการจำลอง (15 ต่อสถานะ) โดยคำนวณเวลาสัมพันธ์กับแต่ละ request
  จึงใช้ทดลอง UI ได้ แต่ไม่ใช่ข้อมูลที่เก็บถาวรหรือหลักฐานทดสอบ live refresh

รายการต่อไปนี้มาจากคำขอของผู้ใช้โดยตรง แต่เอกสารยังคงสถานะ Open จนกว่าผู้ร่วมงานจะยืนยันแนวทางพัฒนาในตารางด้านล่าง

- **ค้นหาและใช้ตัวกรองร่วมกัน:** ค้นหาจากชื่อสินค้า และกรองตามหมวดหมู่ สถานะ วันเวลาประมูล และประเภทประมูล เพื่อช่วยให้ผู้ใช้เลือกสินค้าได้ตรงความต้องการ ข้อแลกเปลี่ยนคือการใช้หลายตัวกรองอาจไม่พบสินค้า ไม่เลือกวิธีใช้ตัวกรองแยกกันเพราะไม่ตรงกับ flow ที่ร้องขอ ที่มา: คำขอผู้ใช้วันที่ 2026-11-11, ไฟล์ requirement และ #63
- **แบ่งตามสถานะการประมูล:** แสดงส่วนที่กำลังประมูลก่อน ตามด้วยส่วนที่ยังไม่เริ่ม และส่วนที่จบแล้ว โดยเรียงตามเวลาปิดที่ใกล้ที่สุด เวลาเริ่มที่ใกล้ที่สุด และเวลาปิดล่าสุดตามลำดับ เพื่อให้เห็นสินค้าตามช่วงเวลาที่เกี่ยวข้อง ข้อแลกเปลี่ยนคือไม่มีลำดับสินค้ารวมทั้งหน้า ไม่เลือกการแสดงรายการรวมเพราะไม่ตรงกับการแบ่งส่วนที่ร้องขอ ที่มา: คำขอปรับ Catalog วันที่ 2026-11-11
- **แสดงรายละเอียดและ Highlights:** การ์ดแสดงรูป ชื่อ หมวดหมู่ สถานะ และประเภทประมูล พร้อมส่วน Highlights ด้านบนที่เลื่อนแนวนอนได้ แสดงสินค้ามูลค่าสูงประมาณ 5 รายการ เพื่อให้ค้นพบสินค้ามูลค่าสูงและเห็นวิธีประมูลได้ง่าย ข้อแลกเปลี่ยนคือสินค้าใน Highlights อาจซ้ำกับส่วนปกติ ไม่เลือกการแสดง Grid อย่างเดียวเพราะไม่ครบตามคำขอ ที่มา: คำขอผู้ใช้ใน #63 วันที่ 2026-11-11

## ข้อเสนอแนวทางพัฒนา — ยังไม่ได้รับการยืนยัน

| หัวข้อ | ข้อเสนอ | เหตุผล / ข้อแลกเปลี่ยน / ทางเลือก |
|---|---|---|
| ความสัมพันธ์สินค้าและการประมูล | แสดง 1 รายการต่อ auction lot โดยอ้างอิงสินค้าและหมวดหมู่เดิม ใช้ข้อมูล auction/lot จาก #28 | สินค้าอาจมีรอบประมูลต่างกันในแต่ละช่วงเวลา การอ้างสินค้าอย่างเดียวจึงไม่เพียงพอ ต้องประสานกับงานเพิ่มสินค้าและ #28 |
| หมวดหมู่ | ใช้หมวดหมู่ที่ตกลงในงานเพิ่มสินค้า ไม่สร้างชุดแยกสำหรับ Catalog | ลดชื่อหมวดหมู่ที่ไม่ตรงกัน แต่รายการหมวดหมู่จริงยังรอยืนยัน |
| ประเภทประมูล | ใช้ค่า `sealed_first_price` และ `english` จาก #28 เสนอชื่อแสดงผล “First-price sealed-bid” และ “English” | ไม่สร้าง enum ซ้ำ ต้องยืนยันคำที่ผู้ใช้ระบุว่า “first-seal bidding” ก่อนสรุปชื่อแสดงผล |
| ตัวกรองวันเวลา | เลือกกรองจากเวลาเริ่มหรือปิด ค่าเริ่มต้นเป็นเวลาเริ่ม รวมค่าที่ตรงขอบเขตตั้งแต่–ถึง เว้นขอบเขตด้านใดด้านหนึ่งได้ หากรูปแบบเวลาไม่ถูกต้องหรือตั้งแต่ > ถึง ให้แสดงข้อผิดพลาดที่ช่อง ใช้เขตเวลา Asia/Bangkok | รองรับช่วงเวลาที่ไม่ระบุปลายด้านหนึ่ง แต่มีตัวเลือกมากกว่าการกรองเฉพาะเวลาเริ่ม |
| ขอบเขตสถานะ | ยังไม่เริ่ม: now < start; กำลังประมูล: start <= now < เวลาปิด lot ที่มีผลจริง; จบแล้ว: now >= เวลาปิด lot ที่มีผลจริง ใช้เวลาเซิร์ฟเวอร์และเวลาปิดล่าสุดรวมการต่อเวลา | ตรงกับลำดับที่ร้องขอ และไม่อ้างเวลาปิดระดับ event ที่อาจไม่เป็นปัจจุบัน |
| สิทธิ์การมองเห็นและกรณีพิเศษ | ไม่แสดงฉบับร่าง รายการยกเลิก และ lot ที่ผู้ชมไม่มีสิทธิ์เข้าถึง หากปิดก่อนกำหนดให้ถือว่าจบตามเวลาปิดจริงที่บันทึกไว้ ต้องยืนยันว่า lot แบบ sealed ที่จบแล้วแสดงได้ก่อนอนุมัติผลหรือไม่ | ป้องกันการเปิดเผยสินค้าที่เข้าถึงไม่ได้หรือยังไม่พร้อม รายการยกเลิกจะไม่อยู่ในส่วนจบแล้ว |
| กรณีเวลาเท่ากัน | ใช้ lot ID จากน้อยไปมากเป็นลำดับรอง | แบ่งหน้าได้สม่ำเสมอ แต่ไม่ได้จัดอันดับความเกี่ยวข้องเมื่อเวลาเท่ากัน |
| รายละเอียดการ์ด | แสดงเวลาเริ่มและปิดในเขตเวลา Asia/Bangkok มีลิงก์ไปรายละเอียดสินค้า/lot และภาพสำรอง | ช่วยอธิบายลำดับและเปิดดูรายละเอียด แต่ route ต้องประสานกับเจ้าของงานหน้ารายละเอียด |
| การโหลดรายการ | ใช้ปุ่ม “โหลดเพิ่มเติม” แยกแต่ละส่วน เสนอครั้งละ 12 รายการ เมื่อเปลี่ยนตัวกรองให้เริ่มรายการใหม่ทุกส่วน พร้อมจำนวนที่พบ ข้อความเมื่อไม่พบ และปุ่มลองใหม่ | เข้าถึงทุกส่วนได้โดยไม่ต้องเลื่อนผ่านรายการยาว แต่ไม่มีเลขหน้าสำหรับข้ามโดยตรง |
| การอัปเดตสถานะ | ดึงข้อมูลทุก 30 วินาทีขณะมองเห็นหน้า และเมื่อกลับมายังแท็บ คงตัวกรองไว้และเริ่มรายการที่โหลดใหม่อย่างสอดคล้องกัน | ทำได้เรียบง่ายบน Rails แต่สถานะอาจช้าถึงหนึ่งรอบและรายการที่ขยายไว้จะยุบเมื่ออัปเดต |
| Highlights | เลือก lot ที่เข้าเงื่อนไขสูงสุด 5 รายการ เรียงราคาเริ่มต้นที่เปิดเผยจากสูงไปต่ำ ตามด้วย lot ID จากน้อยไปมาก ไม่เลือกรายการที่ไม่มีราคา ใช้ตัวกรองและสิทธิ์เดียวกับส่วนปกติ | #28 มีราคาเริ่มต้น `min_price` ข้อเสนอนี้ไม่ใช่ราคาประเมินหรือราคาซองลับ ต้องยืนยันสถานะที่นำมาแสดงและวิธีจัดอันดับก่อนพัฒนา |

ตารางนี้เป็นข้อเสนอของ agent วันที่ 2026-11-11 ยังไม่ใช่ข้อตกลงที่ผู้ใช้ยืนยัน ห้ามใช้ราคาซองลับเพื่อจัดอันดับ Highlights หรือเปิดเผยผ่านข้อมูล Catalog

## กติกาและตัวอย่าง

- lot ที่เริ่ม 10:00 และปิด 11:00 จะยังไม่เริ่ม ณ 09:59 กำลังประมูล ณ 10:00 และจบแล้ว ณ 11:00 เว้นแต่มีการเปลี่ยนเวลาปิดที่มีผลจริง
- หากต่อเวลาปิดเป็น 11:02 ให้ใช้ 11:02 ในการกำหนดสถานะและเรียงสินค้าที่กำลังประมูล
- ตัวกรองประเภทประมูลต้องใช้ร่วมกับคำค้นหา หมวดหมู่ สถานะ และวันเวลา
- ปุ่มล้างตัวกรองต้องล้างประเภทประมูลและเริ่มการโหลดรายการแต่ละส่วนใหม่ด้วย
- ต้องตรวจสิทธิ์เมื่อเปิดหน้ารายละเอียดโดยตรง การกรองรายการใน Catalog ไม่ใช่การตรวจสิทธิ์

## คำถามที่ยังเปิดอยู่

ผู้ร่วมงานต้องยืนยันหรือแก้ข้อเสนอในตารางก่อนปิด #38

1. ยืนยันแหล่งข้อมูลและรายการหมวดหมู่ รวมถึงความสัมพันธ์สินค้า–lot ร่วมกับ #28
2. ยืนยันความหมายของตัวกรองวันเวลา กรณีพิเศษและสิทธิ์การมองเห็น ปุ่มโหลดเพิ่มเติม การอัปเดตสถานะ ชื่อประเภทประมูล และรายละเอียดเสริมของการ์ด
3. ยืนยันฟิลด์ที่ใช้วัดมูลค่าใน Highlights สถานะที่แสดงได้ จำนวน 5 รายการรวมทั้งหมดหรือที่เห็นพร้อมกัน และการใช้ตัวกรองร่วมกับส่วนปกติ (#63)

## งานที่เกี่ยวข้อง

- #39: การแบ่งสถานะ กรณีพิเศษ การเรียงตามเวลา และกรณีเวลาเท่ากัน
- #40: การ์ดรองรับมือถือ รายละเอียด ลิงก์ และภาพสำรอง
- #41: ค้นหาและกรองวันเวลา หมวดหมู่ และสถานะ
- #42: จำนวนสินค้า โหลดเพิ่มเติม ข้อความเมื่อไม่พบ และลองใหม่
- #43: อัปเดตตามเวลา รองรับการต่อเวลาปิด และคงตัวกรอง
- #63: Highlights ชื่อประเภทประมูล และตัวกรองประเภทประมูล
- #44: ตรวจสอบ flow ร่วมกัน สิทธิ์การมองเห็น ขอบเขตเวลา มือถือ และความปลอดภัย

เอกสารนี้ยังไม่ได้เปลี่ยนพฤติกรรมแอป และไม่ได้กำหนดข้อเสนอที่รอยืนยันเป็น Decided
