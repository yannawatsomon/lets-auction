# แบบร่างการแบ่งกลุ่มสินค้า Catalog — issue #39

สถานะ: ผู้ใช้ยืนยันขอบเขต service ในแชตแล้ว (2026-11-11) · Branch: `feat/fon-feature-test`

## เป้าหมาย

เตรียมกติกาแบ่งกลุ่มและเรียง lot สำหรับ Catalog ตามข้อกำหนดที่ผู้ใช้ระบุ
โดยไม่สร้าง auction model ซ้ำกับ #28

## แนวทางที่พิจารณา

1. รอ #28 แล้วทำ query และหน้ารายการจากข้อมูลจริง: ส่งมอบ #39 ได้ครบ แต่ยังเริ่มส่วนเชื่อมข้อมูลไม่ได้
2. ทำ service แบ่งกลุ่มและเรียงข้อมูลก่อน: ทดสอบขอบเขตเวลาได้ทันที แต่ยังต้องเชื่อม model และหน้าเว็บหลัง #28

ข้อเสนอของ agent: ใช้แนวทางที่ 2 สำหรับงานรอบนี้ ไม่ถือว่า #39 เสร็จทั้งหมด

## ขอบเขตที่เสนอ

- เพิ่ม `Catalog::Sections.call(lots:, now:)` คืนค่า hash ที่มี keys ตามลำดับ `ongoing`, `upcoming`, `ended` แต่ละค่าคือ array ของ lot
- แต่ละ lot ต้องให้ข้อมูล `id`, `starts_at`, `ends_at` โดย `ends_at` เป็นเวลาปิดที่มีผลล่าสุด รวมการต่อเวลาหรือปิดก่อนกำหนด
- `now` ต้องเป็นเวลาเซิร์ฟเวอร์ที่ผู้เรียกส่งเข้ามาหนึ่งครั้งต่อการประมวลผล
- ยังไม่เริ่ม: `now < starts_at` เรียงเวลาเริ่มจากน้อยไปมาก
- กำลังประมูล: `starts_at <= now < ends_at` เรียงเวลาปิดจากน้อยไปมาก
- จบแล้ว: `now >= ends_at` เรียงเวลาปิดจากมากไปน้อย
- เสนอใช้ `id` จากน้อยไปมากเป็นลำดับรองเมื่อเวลาเท่ากัน
- ผู้เรียกต้องส่งเฉพาะ lot ที่มีสิทธิ์แสดงผลและผ่านการกรอง draft/cancelled แล้ว service นี้ไม่ใช่การตรวจสิทธิ์
- ข้อมูลต้องมี ID ไม่ซ้ำ เวลาเริ่มและปิดครบ และเวลาเริ่มก่อนเวลาปิด หากไม่ถูกต้องให้ยก `ArgumentError` แทนการเดาสถานะ
- ไม่แก้ไข array ที่ผู้เรียกส่งเข้ามา และคืนทั้งสามกลุ่มแม้ไม่มีสินค้า

## การตรวจสอบ

ทดสอบทั้งสามกลุ่ม การเรียง ขอบเขตเริ่ม/ปิดตรงเวลา เวลาเท่ากัน การต่อเวลาปิด
รายการว่าง ข้อมูลไม่ถูกต้อง และการไม่เปลี่ยนข้อมูลต้นทาง ด้วย Minitest ของ Rails

## งานที่ยังต้องทำภายหลัง

และแสดงทั้งสามกลุ่มในหน้า Catalog ก่อนปิด #39
